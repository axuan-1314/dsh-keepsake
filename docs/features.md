# 功能详解

每项功能按「什么时候触发 / 你会看到什么 / 怎么关掉」写。默认值以源码为准。

## 自动记忆：聊完自己记，下轮自己带

每轮对话正常结束（`turn/end` 且 `reason.kind === "completed"`）后，插件触发一次提取判断。模型看到的是增量对话摘录加现有记忆索引，输出要么是"没啥可记"，要么是一批写/删操作。

每个会话维护一个提取进度游标，只提炼新完成的轮次。提取失败时游标不推进，下一轮连本带利重提，不会漏记也不会重复记。

提取用哪个模型：默认复用你当前对话的模型路由，不用额外配置；也可以在配置里显式指定 `provider` / `model`。

记下来的内容怎么回到对话里：之后每轮，插件把记忆作为一条自有用户消息注入（`<memory-context>` 包裹）。默认走 durable 消息通道，对所有预设生效，包括 `complete: true` 的极简预设。这是 0.2.0 修的坑——以前走 systemPrompt，极简预设下会静默失忆。想回退旧通道就设 `injectChannel: "section"`。

注入的内容分六段：

| 段 | 内容 | 预算 |
|---|---|---|
| 人设 | 称呼 + 你编辑的补充人格 | 400 行 / 8k 字符 |
| 运行时用户画像 | 开启运行时记忆后，由条目编译的 `USER.md` | ≤ 4096 字节 |
| 运行时工作记忆 | 开启运行时记忆后，由条目编译的 `MEMORY.md` | ≤ 10240 字节 |
| 全局记忆索引 | 四个分类的条目索引，近期动态带年龄和过期倒计时 | 每类 22 行，总 120 行 / 12k 字符 |
| 项目使用说明 | 记忆目录在哪、索引怎么读 | 固定短文 |
| 项目记忆索引 | 该项目 `MEMORY.md` 的索引 | 200 行 / 25k 字符 |

人设和两段运行时是锁定段，不参与整段丢弃；只有后三段会被预算挤掉。索引段放不下时先降级成紧凑索引（分类计数 + 最新几行 + 完整索引路径），还装不下才整段丢。

面板「设置」页有三层开关，改完下一轮生效：

| 开关 | 关掉之后 |
|---|---|
| 对话记忆（总开关） | 注入全停、提取全停。关掉期间的轮次不积累，重开不回补 |
| 项目记忆 | 项目和运行时段不再注入，项目类写入被过滤（计数可见） |
| 全局自动提取 | 不再自动写全局记忆，已有条目照常注入 |

防自反馈：注入的记忆消息带 `source.kind = "plugin:dsh-keepsake"` 标记。提取侧按统一的机器来源判据，把任意插件注入的消息、以及 instruction / summary / tool 这类系统性消息都从"用户散文"里排除掉。这样不会出现模型把记忆又记回记忆的自食循环。真人消息（含无来源、steer / followup）永远算数。

提取要花 token，所以三道成本闸都默认开着，各自有独立开关：

- 打分门（`extractGateEnabled`，阈值 `extractGateMinScore` 默认 6）：分数 = 用户词数 + 2×工具种类数 + 2×真人轮次数。不过门就记 `skipped/thin-evidence`，不调模型，纯寒暄的薄轮次不再白花一次调用。
- 空闲延迟（`extractIdleDelayMs` 默认 3000ms，0 = 立即）：轮结束后等 3 秒，期间新完成的轮次合并进同一批。插件退出时会话会立即收口，不丢最后一轮。
- 每会话上限（`extractMaxRunsPerSession` 默认 50，0 = 不限）：到顶后记 `skipped/session-cap` 并推进游标。只约束自动链路，面板手动补提不受限。

记忆分两层。全局记忆有工作背景、用户个人背景、当前关注、近期动态四个分类，外加长期记忆（归档区）；近期动态自动滚动清理，默认保留 30 条 / 30 天。项目记忆按工作区路径隔离，每个项目一个目录。

## 记忆管理面板

入口在 DSH 设置页「记忆」区块 →「打开记忆管理」。打开方式三级降级（新窗口 → 内嵌 iframe → 整页跳转），主题自动跟随宿主深浅色。

门牌本身也能操作：总开关、「DSH 的名字」「对我的称呼」两个输入框（防抖自动保存）、状态摘要、提取失败红条加详情深链。

面板里的页面：

- 四个对话分类加长期记忆页。条目卡片流，支持检索（即时过滤，每页 50 条分页）、编辑（标题 60 字、描述 60 字、正文 20000 字符，实时显示字符与字节数）、删除（确认弹窗）、新增。
- 源码模式。整类序列化成一个文本框直接编辑，保存等于先自动备份再整类重建。
- 导入。上传 `.json` / `.md`（≤2MB）或粘贴，支持三种格式（JSON 逐条 / Markdown 按 `##` 拆条 / Markdown 整段）。先预览冲突项并标红，确认才落盘；批内同名自动 `-2` / `-3` 避让。
- 人设页。Markdown 编辑加实时预览，五个预设模板（简洁 / 专业 / 幽默 / 伙伴 / 自定义），上限 100KB。人设是对官方系统提示的补充，不是替换。
- 称呼页。各 40 字上限，防抖自动保存。
- 项目记忆页。只读概览，按工作区列条目数与最后更新，可单项目导出 JSON。项目记忆由对话自动维护，不提供手工编辑。
- 回收站页、快照页、运行时记忆页、最近活动页，见本文对应章节。
- 设置页。三层开关、运行时记忆开关、管道健康卡、提取模型卡、记忆整理卡、嵌入服务卡、保留策略、数据卡（导出全部 / 清空全部）、备份列表。

损坏可见：`settings.json` / `addressing.json` / `persona.md` 解析失败时，门牌和面板显示红条「解析失败（已按缺省运行）」，点任意开关或重存对应内容即可重写修复。损坏档在覆盖写前自动备份成 `*.corrupt-<ts>`。`settings.json` 损坏时还会从影子档 `settings.last-good.json` 尝试恢复你的开关，恢复不了才落默认。

## 内容脱敏

默认开。密钥这类东西不该被记下来，在两道位置拦。

第一道在进提取提示词之前：会话摘录渲染时就脱敏，再截断。顺序刻意是先脱敏后截断，防止截断把密钥切成两半漏检。

第二道在落盘之前：提取产出的写/删操作在写文件前再过一遍。这一道同时处理正文内容字段和文件名——密钥被写进文件名时会落盘、进索引、随每轮注入，比正文里的更持久。文件名命中后追加源名短指纹（`[redacted]-<8位十六进制>`）保证不撞名。

内置 7 类固定模式，不支持自定义正则（防 ReDoS）：

1. 私钥块（`-----BEGIN ... PRIVATE KEY-----` 整块）
2. Authorization / Proxy-Authorization 头里的凭据
3. 独立出现的 Bearer / Basic 令牌（16 字符以上）
4. 常见厂商密钥形态：`sk-`、GitHub PAT（`ghp_` 等）、AWS Access Key（`AKIA`）、Slack（`xox`）、Google API Key（`AIza`）、JWT（`eyJ` 三段式）
5. URL 内嵌凭据（保留协议与主机，凭据换占位符）
6. 敏感键值赋值（`password` / `secret` / `token` / `api_key` 等键名后跟 `:` 或 `=`）
7. 内网 IPv4（`10.x`、`172.16-31.x`、`192.168.x`）

命中替换为 `[redacted]`，对已脱敏文本重复执行不再变化（幂等）。命中数记进提取运行日志的 `redacted` 字段。不想用就把 `redactionEnabled` 设成 `false`。

## 运行时记忆层（可选，默认关）

把条目编译成两份定长紧凑记忆（`USER.md` 用户画像加 `MEMORY.md` 工作记忆），随每轮注入，不用等模型按索引主动 Read。

链路是：条目 →（编译）`runtime/<scope>/USER.md` / `MEMORY.md` → 注入。真源永远是条目文件，产物可删可重建，手改产物会被下次编译覆盖。

配额是 `USER.md` ≤ 4096 字节、`MEMORY.md` ≤ 10240 字节（UTF-8 字节口径，含文件头与告警行）。这是编译期常量，面板和配置都不提供调高。标了 `pinned: true` 的条目优先入选、永不淘汰。

装不下的条目不会静默消失。顺序装填装不下即停，被淘汰的记进清单 `evictCandidates[]`，产物末尾留一行 `[runtime evicted: N entries …]`。只要该分类还有条目没进产物，这个分类就继续留在全局索引里，所以任何一条记忆至少有一个可见入口。

淘汰走「候选 + 确认」：编译只登记候选，绝不搬文件。你在面板勾选后点「执行归档」才真正搬进 `global/long-term/`。归档前对每个文件做手术式快照（`backups/evict-<ts>/`，保留最近 10 份），并追加持久审计 `evict-audit.jsonl`。面板「从归档移回」按条目里记录的出处（`originProject` / `originType` / `originSessionId`）落回原位。

预算账：persona 段上限 8000 字符（约 12000 tokens），加上 runtime 两段常驻约 14336 字节（约 7170 tokens），共约 19170，小于 `injectMaxTokens` 的 24000。

要回滚就把「运行时记忆」开关关掉，回到不编译不写盘的旧形态，`runtime/` 目录可以整个删掉，不损失任何记忆。

## 语义召回（可选，默认关）

开启 `recallEnabled` 并配好嵌入端点后，每轮按你当前的问题做向量检索，取余弦 top-k，以 `<memory-recall>` 块注入。

默认关意味着不配端点就不产生任何外部调用，记忆文本不出本机；指向本地端点则全程不出本机。

面板设置页的「嵌入服务」卡可以直接填端点、模型、API Key，带「测试连接」按钮。保存后下一轮生效，不用改配置文件、不用重启。已保存的 Key 只发往它自己配置的那个端点——请求指向别的地址时不会把已存密钥带过去。Key 输入框留空表示保留已存密钥，要清空得点「清除已存 Key」。

插件不绑定任何厂商。只要你的服务提供 OpenAI 兼容的嵌入端点，填上地址和模型名即可；`embeddingProvider` 只是面板显示标签。

配置不全时插件照常启动，召回被显式关闭（零嵌入调用），面板出红条说明缺哪个键、去哪补，补齐后不重启即恢复。端点配齐但超时或报错时，本轮不召回（不阻塞、不臆造），计数进 `/state.recall`，面板出红条；连续失败 3 次后自动暂停 60 秒。

## 项目知识页（手动生成）

把一个项目的记忆合成 5 页稳定视图：组件地图、核心概念、约定与模式、关键决策、进行中事项。参照 hindsight 的 knowledge-page taxonomy，但保持本地 markdown、零依赖、单次 LLM 调用。

页面是派生视图，不是真源。落在 `<storageRoot>/pages/<projectId>/`，可删可重建；条目仍是唯一真源。

生成是手动的：面板「项目记忆」页 → 项目卡片「知识页」→「生成 / 重新生成」。一次点击等于一次 LLM 调用，不随提取自动触发。

注入时只带页面摘要（标题 + 一行钩子 + 路径），排在原始项目索引之前；模型要细节时按路径 Read。记忆变了会标 `[stale]`。

解析、调用、落盘任一失败都保留上一版 manifest，不会拿半成品覆盖旧页。落盘本身是两阶段的：先全部写临时文件（失败只清临时文件，现场零改动），再统一换入；换入阶段失败会整体回滚到旧版。

## 空闲整理（默认关）

有新增项目记忆时，空闲后让模型做一次合并、更新、清理的审查。

触发条件是提取结算 `written`（确实写了新条目），随后延迟 60 秒起跑，避开你正在进行的轮次。闸门是每会话两次审查最小间隔 10 分钟、最多 5 次，且全局单飞。

产出最多 3 个 project-scope 操作（write / delete）。提示词要求合并近重复、更新过期、清理废弃，不碰全局记忆。落盘仍走批锁、快照、sha1 闸、写后校验，delete 进回收站。

模型只提案，插件落盘。解析失败、调用失败、落盘失败都只记状态和日志，不中断提取主链路。

开关在面板「设置」页「空闲整理」，对应 `settings.json` 的 `idleReviewEnabled`（缺省 false）。

## 纠错闭环

把"这条记错了"变成一次可回滚的修正。

此前提取和整理只会写和删，模型无法表达"这条错了，正确的是 X"。错误事实只能靠下一轮提取碰巧覆盖，实际常留下两条互相矛盾的记忆。

两个入口走同一条通路：对话里 `/memory fix <关键词> | <诉求>`，或面板「最近活动」页检索后点「纠正这条」。两者都走 `lib/corrections.js` → `applyScopedOps`。

提示词明令禁止顺手整理无关条目，邻域只给同 scope 的索引（用于识别重复），不给别的正文。

结局有三种，都如实回报。`applied` 表示已改，附改写/删除条数；`needs-input` 表示诉求不够具体、模型明确拒绝改动、记忆一字未变；`nothing` 表示判断无需改。`needs-input` 不算失败——你什么都没做错，只是话没说到位。

操作全被闸拦下（sha1 不符 / 锁冲突 / 写后校验失败）时判失败，不写"已纠正"记录。落盘走和自动提取完全相同的安全面，delete 进回收站。每次应用记进 `correction-ledger.jsonl`，坏行跳过，不因一条脏行挡住整份记录。

面板检索结果可以勾多条一次提交（上限 10 条）。每条独立一次调用、独立成败，不做成一次大调用——合成一次会让一条的诉求污染另一条，且任一条失败会拖垮整批。结局分三档：`applied`（全成）、`partial`（部分成，逐条列明）、`error`（全败）。超过上限显式报 400，不静默截前 N 条。

纠错记录卡有「按时间」和「按条目」两个视图。按时间答"最近改了什么"，按条目答"这条改过几次、每次改了什么"。归组只算真正改了盘的操作，`needs-input` / `nothing` / `failed` 混进来会让次数虚高。

## 最近活动

提取、注入、整理、纠错的观测原先分散在四个地方。面板「最近活动」页把它们按时间窗归并成一条时间线。

归并口径如实：提取事件自带会话号，按会话精确匹配；注入、整理、纠错是进程级或显式动作，只按时间窗落进流里，不编造因果。

窗口默认最近 30 分钟，可切 10 分钟 / 30 分钟 / 1 小时 / 3 小时 / 1 天。请求超过一周会被钳到一周并如实回报实际窗口。

空态分两种措辞：「宿主未提供活动数据」（旧版或未接线）和「最近 N 分钟内没有活动」。

## 记忆检索

对话内用 `/memory`（列最近条目）、`/memory <关键词>`、`/memory why <关键词>`（附命中位置与相关度）、`/memory fix`、`/memory forget`。面板内是「最近活动」页的检索框，结果每条带「纠正这条」。

打分口径：名字完全相等 100，名字包含 60，标题 45，摘要 30，正文 15；多关键词 AND。故意不做 tf-idf，因为用户问"我记得那条叫什么"时，需要一个能讲清楚为什么排第一的规则。

正文和查询两侧统一做 NFKC 加小写折叠，所以 `ＰＮＰＭ` 和 `pnpm` 互查得到。索引文件 `MEMORY.md` 不参与检索——它不是条目，混进来会让每次查询都命中它。

## 失败韧性与安全面

单次提取最多 3 个 attempt（含首次），指数退避 500ms 起步、2s 封顶，jitter ±20%。上游带 `Retry-After` 时优先采用。插件卸载或进程退出时退避立即中断。

失败按内核 `failure.code` 分类：EMPTY_RESPONSE / RATE_LIMIT / SERVER / TIMEOUT / TRANSPORT 可重试；AUTH / INVALID_REQUEST / QUOTA 这类确定性失败立即摊牌，不浪费 attempt。

主道 attempt 链耗尽后，按 `fallback` 配置逐条换道。未配置时行为和纯重试完全一致。

无路由、无 cwd 这类重试不可能自愈的失败，连续 5 次后显式放弃该区间并记日志，不无限积压。

会话补提让失败区间跨重启看得见（0.4.1）、补得上（0.4.2）。面板「补提」区列出未恢复和已放弃的区间，逐条可点「补提」重跑。自动收口（`autoRecoverEnabled` 默认开）在三个时机自动补：会话关闭时、每轮完成后、插件装载后数秒。只补未恢复的失败区间，已显式放弃的绝不自动重试，同一区间两次自动补提之间冷却 5 分钟。补提区间必须整体落在会话可读范围内；超出（含超大会话读回截断后的尾部）的显式拒绝，继续留在清单里，不会把没读到的部分按已补提记账。

写入可逆性分几层：

- 批前快照（项目侧）。一批里要覆写或删除的旧文，落盘前先留档到 `backups/surgical/<batchId>/`，保留最新 30 份。面板「快照」页可整份恢复或只恢复某个文件。
- 回收站。删除不再硬删，先进 `trash/<entryId>/` 落副本，确认副本落稳再删原件，默认保留 30 天。覆盖自动提取的删除和面板手动删除；分类重置和近期动态滚动清理仍是直接删（重置前另有整类备份）。
- 写后读校验。落盘后回读校验 frontmatter 四字段与正文，校验失败回滚旧文。
- 硬事实守护。覆写把既有硬事实（数字、版本号、十六进制标识、字节尺寸）弄丢时留痕告警；`hardfactPolicy` 设 `block` 则回滚该操作，默认 `warn` 只告警。
- 写路径三道闸。覆写只在带对期望 sha1 时发生；不带 sha1 的盲写不覆盖旧正文，降级为追加；提取落盘抢批锁。
- 覆盖前自动快照。改写既有条目前先留档，快照失败则跳过这次覆盖，原文保持不动。面板手动保存同样先留档，留档失败直接拒绝保存。
- 恢复前也留档。从快照、回收站、整份备份恢复前，先对冲突文件留快照。

真源只有 `*.md` 和 `MEMORY.md`。`backups/` 和 `trash/` 是可安全删除的副本目录，删掉不损失当前记忆，只失去回滚能力。

## 自动备份

所有批量破坏性操作都有后悔药。重置分类、确认导入、恢复备份、重置人设、清空全部之前，自动把全局记忆（含人设与称呼）、`settings.json`、项目记忆全量备份到 `backups/<时间戳>/`，滚动保留最新 20 份。

备份用两段式落盘（先 `complete: false`，拷完改 `true`），中断的半备份在面板标「不完整」且拒绝恢复。恢复备份前会先把当前状态再备份一份，恢复中途失败时响应会带上这份备份的 id 指路自救。

## 记忆整理

设置页「记忆整理」卡只出建议，不自动改动。

重复建议会列出正文高度重叠、跨分类同名、标题相近且正文重叠的条目对，附相似度与判断依据。只提示，留哪条由你决定。

久未更新提醒默认 90 天，修改时间缺失的如实标「年龄不可知」，不拿 0 天冒充。

索引健康把 `MEMORY.md` 和磁盘对账（悬挂行、漏登记、空分类）。一键修复只增删索引行，绝不删条目文件；改动前先把索引原文存进快照，留档失败就拒绝本次修复。
